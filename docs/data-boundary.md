# 数据边界与公开发布规则

## 三类内容

| 类型 | 存放位置 | 是否进入公开 Git | 说明 |
|---|---|---:|---|
| `local_observation` | 本地私有研究资料库 | 否 | 真实公开页面、授权可见页面、来源原件和观察记录 |
| `public_rewrite` | 仓库中的抽象文档或 Fixture | 是 | 删除学校专名、真实入口、个人信息和可反推细节后的机制描述 |
| `virtual_design` | 仓库中的种子数据与测试 | 是 | 为演示和评测设计的虚拟地点、角色、规则、档期和状态 |

## 允许公开什么

- 通用业务问题和抽象领域模型；
- RAG、Agent Runtime、Workflow、评测和前端的实现方法；
- 不指向现实系统的示例数据；
- `example.invalid` 等不可解析域名；
- 可复核的代码、测试和本地运行命令。

## 不允许公开什么

- 真实学校页面的复制内容、正文片段、截图、下载文件或接口响应；
- 具体校园地点、部门、责任人、内部编号、审批链、联系方式和当前时限，除非已被彻底抽象为虚拟设计且不会被误读为官方事实；
- 登录状态、账号、Cookie、Token、个人记录和业务回执；
- 本机路径、私有技术资料库路径、聊天记录和内部 Agent 运行日志；
- 任何能让读者直接访问真实业务系统或复原未公开规则的链接。

## 发布前检查

1. 对工作树和 Git 历史做敏感信息扫描。
2. 检查代码、测试、构建产物、图片元数据和文档链接。
3. 检查 Issue 标题、正文、评论和自动生成内容。
4. 把所有现实观察改写成“问题机制”，把演示数据标记为 `virtual_design`。
5. 确认 README 明确写出非官方、无背书、未接入真实系统。
6. 先在本地做完整测试，再单独确认远程历史重写和外部 Issue 变更。

远程内容一旦公开，编辑当前文件不等于清除旧提交、Issue 编辑记录、评论、缓存或他人克隆。公开发布前必须先完成清理，再进行首次推送或历史替换。
